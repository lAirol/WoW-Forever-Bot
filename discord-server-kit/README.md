# WOW forever team — подготовка Discord-сервера

Подготовлено 23.10.2026. Живой сервер **WOW forever team** уже создан и настроен через интерфейс Discord; фактическое состояние описано в [LIVE-STATUS.md](LIVE-STATUS.md). Файлы установщика сохранены как комплект для повторного развёртывания на отдельном сервере. Не запускайте его поверх выполненной вручную настройки. Установщик настраивает уже созданный сервер: роли, категории, каналы, разрешения и стартовые сообщения.

## Состав

- 28 ролей: 9 служебных/групповых, 9 классовых и 10 расовых.
- 6 категорий, 16 текстовых и 2 голосовых канала.
- Входная зона для участников без допуска; закрытые разделы команды; операторская и расчёты отдельно.
- Правила, анкета, шаблоны смен, карточек заказа, отчётов и инцидентов.
- Установщик без внешних Python-зависимостей, план без подключения к Discord и тесты.

Роли предпочтений не открывают рабочие разделы. Допуск выдаётся ролью «Исполнитель», «Лидер группы» или «Оператор». Роль «Владелец команды» — обычная роль доступа; она не меняет настоящего владельца сервера и не выдаёт Administrator. Администраторы Discord и реальный владелец могут видеть закрытые каналы по правилам Discord.

## Опрос на живом сервере

Включены «Сообщество» и встроенная адаптация Discord. Три обязательных вопроса выдают игровые роли: основной класс, танк/хил/дд (несколько вариантов), раса. Ответы можно изменить в «Каналы и роли». Ник, уровень, специализация, альты и время игры указываются в #анкеты-кандидатов. Игровые роли не дают рабочего допуска.

Установщик создаёт роли и каналы, но не включает Community и не публикует вопросы адаптации. На новом сервере эту часть необходимо настроить через Discord отдельно.

## Как применить

1. В Discord создать пустой сервер на аккаунте будущего владельца. Не использовать для этого чужой аккаунт. Достаточно обычного сервера; платная подписка не требуется для этого комплекта.
2. В [Discord Developer Portal](https://discord.com/developers/applications) создать приложение и бота. Токен хранить у себя; в чат его не присылать.
3. Взять Application ID и получить ссылку приглашения:

```powershell
python .\setup_server.py --invite APPLICATION_ID
```

4. Открыть ссылку и добавить бота в нужный сервер. Установщик запрашивает Manage Channels, Manage Roles, View Channels, Send Messages, Embed Links, Read Message History. Administrator не нужен и установщиком отвергается. Manage Roles — чувствительное право: бот может управлять ролями ниже своей роли. В интерфейсе разместить роль бота выше новых рабочих ролей, но ниже существующих административных ролей. После установки бота можно удалить, если он больше не нужен.
5. В настройках Discord включить режим разработчика и скопировать ID сервера. Уточнить его точное название.
6. Посмотреть план без сети и токена:

```powershell
python .\setup_server.py
```

7. Применить к выбранному серверу:

```powershell
python .\setup_server.py --apply --guild-id SERVER_ID --expected-name "Точное название сервера"
```

Токен бота вводится скрыто в терминале и не записывается в файл. Альтернатива — заранее заданная безопасным способом переменная окружения `DISCORD_BOT_TOKEN`. Не вставлять токен в команды/аргументы, исходники, конфиги, заметки и историю PowerShell. Скрипт не запрашивает пароль пользовательского аккаунта и не использует user token/self-bot.

Имя сервера установщик не меняет. `name` в конфиге — рабочее название проекта. `--expected-name` защищает от применения к ошибочному серверу.

## Повторный запуск и изменения

Состояние сохраняется рядом с программой в `setup-state-SERVER_ID.json`: только ID созданных объектов и сообщений, без секретов. Сохраните его. Повторный запуск с тем же конфигом не дублирует записанные объекты. Чужие существующие каналы/роли не изменяются; совпадение имён останавливает работу.

Сетевой сбой во время создания может дать неоднозначный результат: объект мог появиться, хотя ответ не получен. Скрипт останавливается вместо слепого повтора. Проверьте фактический сервер и файл состояния перед повтором. Не удаляйте состояние ради повторного запуска.

Это установщик, не универсальный редактор: изменение конфигурации после применения не обновляет уже созданные объекты. Для правок используется Discord UI или отдельная проверенная миграция. Финальная проверка установщика сверяет права каналов с конфигурацией; при расхождении останавливается.

## Проверка владельцем после установки

- Участник без рабочих ролей видит только начало и вступление.
- Исполнитель видит команду, набор и общий голос, но не диспетчерскую/расчёты.
- Оператор видит операторскую и может публиковать карточки.
- Исполнитель не может писать в каналы с правилами и доску набора.
- Роли «Танк», «Хил», «дд» не дают допуск сами по себе.
- Выдайте себе/оператору нужные роли вручную.
- Анкеты видны участникам входной зоны: в них разрешены только несекретные игровые сведения. Для приватных анкет позже подключается отдельный тикет/форма.
- Для каждого реального заказа создавайте отдельную закрытую комнату с персональными разрешениями. Общих голосовых каналов недостаточно для приватного обсуждения покупателя.
- В настройках безопасности вручную включите AutoMod и проверьте 2FA владельца. Установщик не обещает, что AutoMod уже включён.

## Что ещё не подключено

Нет действующих интеграций FunPay/G2G, кнопочного набора, реестра с бронированием времени, автосоздания комнат заказов, начислений и платежей. Стартовые сообщения честно описывают ручной режим. Этот комплект создаёт основу сервера; постоянный Operations Bot — следующий отдельный этап.

## Проверка локально

```powershell
python -m unittest discover -s . -p "test_setup.py" -v
```

Тесты проверяют закрытый доступ, наследуемое право отправки, повторный запуск, ошибочный сервер и совпадение имён. Они используют симуляцию API и не изменяют Discord. Проверка реальных разрешений Discord требует бота и тестового участника.
