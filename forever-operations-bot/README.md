## Возможности бота

- `/персонаж`: ник, мир, класс, специализация, раса, уровень, тип брони и роли через запятую: `танк, хил, дд`. Повторение ника и мира обновляет карточку. Каждый альт добавляется отдельно. До 25 персонажей на участника.
- `/персонажи`: личный список с номерами. Другие участники не видят его. Персонаж, выбранный для активности, становится виден участникам её канала в составе.
- `/удалить-персонажа`: удаляет только свою карточку без истории записей. Карточки, связанные с историей, сохраняются.
- `/сбор`: лидеру — название, начало со смещением UTC, длительность и количества мест по ролям. Необязательные параметры: `максимум` (равен сумме мест, 1–40), `классы` (через запятую), `броня` (ткань/кожа/кольчуга/латы). Оба фильтра применяются одновременно и к основе, и к резерву. Работает только в #сбор-группы и #набор-на-заказы.
- На карточке: танк / хил / дд, резерв по каждой роли, «Готов», «Отказаться», полный состав файлом.
- При записи выбирается свой персонаж с соответствующей ролью. Полный слот или пересечение времени переводят в резерв. При освобождении места повышается первый подходящий участник; занятость учитывается по Discord-пользователю, включая его альтов.
- Периодическая проверка повышает резерв и после снятия конфликта с другой активностью. После повышения готовность нужно подтвердить заново.
- `/состояние`: набор → сбор → идёт → завершён; отмена доступна из незавершённых состояний. «Сбор» фиксирует состав и создаёт закрытый текстовый канал в «09 · АКТИВНОСТИ»: основа, организатор, операторы и бот; администраторы Discord сохраняют доступ. Резерв не допускается. При возврате к набору права комнаты пересчитываются при изменении состава. Через 60 секунд после завершения/отмены канал и его переписка удаляются. Начать можно только с полным составом и готовностью каждого. Возврат из «сбор» в «набор» снимает готовность.
- Напоминание основному составу примерно за 15 минут, если бот в сети. Время в карточке показывается средствами Discord в локальном часовом поясе зрителя.
- `/мероприятие`: создаёт настоящее мероприятие Discord в выбранном гильдейском голосовом канале. Запись по ролям и мероприятие пока создаются отдельно; взаимной синхронизации отмен/переносов нет.
- `/панель-обращений`: оператор публикует кнопку в #вопросы-команде. Один участник может иметь одно открытое обращение.
- Комната обращения: автор + операторские роли + бот. Администраторы Discord сохраняют штатный доступ. `/закрыть-обращение` закрывает обращение и удаляет канал с перепиской через 60 секунд. Автоматическая копия сообщений не сохраняется. Уже закрытые до обновления обращения автоматически не затрагиваются; старое открытое обращение перейдёт на удаление при закрытии после проверки ID, имени и категории.
- `/обновить-сбор`: восстановить отображение карточки из базы. `/привязать-сбор`: связать сохранённый сбор с уже существующей карточкой бота после неоднозначного сетевого сбоя.

Бот не проверяет игровые достижения, совместимость класса и расы или реальную квалификацию; данные вводят участники. Он не играет за людей, не закрывает автоматически заказы площадок и не назначает выплаты. Завершение активности подтверждает лидер.

## Подключение

1. Создать приложение **Forever Operations** в [Developer Portal](https://discord.com/developers/applications). Принятие условий выполняется только после подтверждения владельца.
2. Установить приложение только на WOW forever team со scope `bot` и `applications.commands`. Нужные разрешения: View Channels, Send Messages, Embed Links, Read Message History, Attach Files, Manage Channels, Manage Roles и Create Events. Число разрешений: `17592454597648`. Administrator не требуется.
3. Manage Roles нужен для индивидуальных разрешений комнат, включая закрытие записи автора. Это чувствительное право: разместить роль бота ниже административных/операторских ролей; бот сможет управлять обычными ролями ниже себя. Установка с этими правами требует отдельного подтверждения владельца в Discord.
4. Явно дать роли бота доступ к двум доскам набора, категории обращений и выбранным гильдейским голосовым каналам. Закрытые категории могут перекрывать глобальное View Channels. В операторскую/расчёты давать доступ ко всей категории не требуется.
5. Оставить Message Content Intent и Server Members Intent выключенными. Команды и кнопки используют взаимодействия; чтение всех сообщений не требуется.
6. Выпустить токен бота в Developer Portal и ввести его **самостоятельно в скрытый запрос терминала** при запуске. Не отправлять токен в чат, не класть в конфиг, `.env`, заметки или исходники. Токен нужен только процессу бота. Альтернатива для готовой инфраструктуры — безопасно предоставленная переменная окружения `DISCORD_BOT_TOKEN`; не вводить её значение в команду, сохраняемую в истории.
7. Уточнить `config.json`, если роли или каналы переименованы. Роли сравниваются без учёта регистра, совпадение двух операторских ролей с одинаковым названием останавливает создание обращения.

## Подготовленная локальная форма

В текущей сессии запущен `launcher.py` на `http://127.0.0.1:55358/`. Это адрес только этого компьютера. Владелец сам выпускает токен в Developer Portal → Бот и вводит в поле типа password. Форма не записывает его в файл, чат, аргументы процесса или журнал: токен передаётся дочернему процессу только в окружении. После отправки открывается страница состояния.

Для повторного запуска формы использовать Python из окружения с зависимостями: `python launcher.py`. Порт будет выбран заново и напечатан в терминале. Одновременно запускать только один экземпляр launcher.py/бота. Локальный запуск не обеспечивает работу при сне/выключении ПК. Токен не сохраняется между запусками.

## Запуск на Windows

Нужен Python 3.12+. Выполнить из этой папки:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe bot.py
```

При отсутствии Python в PATH можно использовать поставляемый с Codex интерпретатор, указав его полный путь вместо `python`.

По умолчанию база хранится рядом с `bot.py` в `data.sqlite3`. Для постоянного запуска задать `FOREVER_DATABASE` путём к выделенному каталогу данных; это путь, не секрет. Процессу нужны права записи в каталог базы. Запускать **один экземпляр** бота. Пока он запущен на домашнем ПК, выключение/сон/потеря интернета останавливают кнопки и напоминания. Для круглосуточного режима нужен постоянно работающий хост; он этим комплектом не приобретается и не развёрнут.

После подключения выполнить в #вопросы-команде `/панель-обращений` один раз. Затем провести проверку ниже и обновить сообщение #сбор-группы о запуске автоматизации. Реальных рейдов без согласованного расписания не создавать.

## Сквозная приёмка на живом сервере

Локальные тесты не заменяют этот этап:

1. Добавить двух тестовых персонажей на двух аккаунтах и создать явно тестовый сбор с одним местом дд.
2. Записать первого в основу, второго — в резерв. Отказ первого должен повысить второго и снять готовность.
3. Создать пересекающуюся активность: один человек не должен занять два основных места одновременно, даже на разных альтах.
4. Перезапустить процесс и проверить старые кнопки, состав, готовность и очередь.
5. Зафиксировать состав; запись и отказ должны закрыться. До подтверждения готовности запуск должен отклоняться.
6. Отметить тест завершённым. Это не должно менять площадочные статусы или начисления.
7. Открыть обращение обычным участником: посторонний/согильдеец не должен видеть комнату, автор и оператор должны. Закрыть и дождаться удаления через минуту; повторный вопрос создаёт новую комнату.
8. Создать тестовое мероприятие в закрытом гильдейском голосе, проверить видимость согильдийцу и отсутствие видимости кандидату. Затем убрать тестовое мероприятие с обычным подтверждением удаления.

## Сбои и сохранность

- SQLite транзакции защищают последнее место и одну активную комнату от одновременных кликов. Повторная запись одного человека не создаёт дубль. Изменение карточки персонажа не переписывает старый состав: запись хранит снимок.
- После успешной записи в базу и неудачного редактирования сообщения состояние уже могло измениться. Оператор использует `/обновить-сбор`; повторное создание активности не требуется.
- Неоднозначный ответ при публикации: проверить канал и номер сбора. Если карточка появилась, использовать `/привязать-сбор` с её ID. Бот намеренно не пересылает новую карточку вслепую.
- Неоднозначное создание обращения отмечается `проверить`, повторное создание блокируется. Бот ищет созданный канал по сохранённой уникальной метке в теме и восстанавливает связь. Если канал с меткой не найден, повторное создание остаётся заблокировано до проверки оператором. Комната состава использует тот же механизм; создавать дубль вслепую бот не будет.
- Напоминание отмечается отправленным до сетевого вызова, чтобы таймаут не вызвал повторные пинги. При сбое напоминание может быть пропущено. Не считать его гарантией явки.
- Сохранять резервную копию базы при остановленном процессе, отдельно от исходников. База содержит игровые профили и Discord ID; хранить её с ограниченным доступом, не публиковать. Очередь удаления временных каналов хранится в базе и переживает перезапуск. Если бот выключен, удаление произойдёт после подключения. Перед удалением проверяются ID, сервер и уникальная метка темы; при смене метки автоудаление останавливается. Не редактировать технические темы временных комнат.
- При удалении временного канала Discord удаляет и его сообщения. Бот не выгружает тексты обращений; минимальные записи событий и обращений остаются в базе. Платежи и игровая автоматизация не выполняются.

## Лимиты, фильтры и временные комнаты — 24.10.2026

Пример обычной группы: `/сбор название:Группа начало:2026-11-01T20:00+03:00 минут:60 танков:1 хилов:1 дд:3 максимум:5`.
Пример добора только кольчуги: `/сбор название:Кольчуга начало:2026-11-01T20:00+03:00 минут:60 танков:0 хилов:0 дд:3 максимум:3 классы:Охотник,Шаман броня:кольчуга`.
Класс и броня в `/сбор` — общие ограничения. Дополнительные требования к отдельным местам настраиваются через `/требование-сбора`; лимит повторов класса — `/повторы-класса` (см. раздел ниже).

Тип брони задаётся явно в `/персонаж`; из класса он не угадывается. Старые профили без брони нужно обновить перед записью в сбор с фильтром брони. Класс/броню персонажа нельзя менять, пока у него есть незавершённая запись; сначала снять запись (для зафиксированной группы лидер возвращает статус «набор»). В карточке остаётся снимок данных на момент записи.

Комната создаётся при фиксации (`/состояние статус:сбор`), без ожидания заполнения всех мест; начать активность можно только с полным готовым составом. Создаётся текстовый канал; отдельный голосовой канал эта версия не создаёт. Организатор имеет доступ к комнате, даже если не занимает игровое место.

Живая проверка: технические сборы №2 и №3 с максимумом 1, классом Маг и бронёй ткань. Проверены права через официальный API, создание комнат, завершение и запланированное удаление. Во время минутного ожидания процесс перезапущен; результат удаления проверен отдельно через Bot API. Подробные результаты — ACCEPTANCE.json. Одновременное обновление карточки защищено отдельной блокировкой и тестом создания ровно одной комнаты. Общая локальная проверка — 29 тестов. Пользовательский тест с двумя обычными аккаунтами остаётся отдельным этапом приёмки.

## Списки карточек и селекты — 24.10.2026

`/карточки` открывает личный интерактивный список зарегистрированных через `/персонаж` карточек. Доступ: владелец сервера, Владелец команды, Оператор, Лидер группы. Права и автор меню проверяются заново на каждом выборе/экспорте. Списки не публикуются общедоступным сообщением.

Фильтры команды: `роль` (игровая роль), `класс`, `броня`, `мир`, `раса`, `специализация`, `от`/`до` (уровни включительно), `участник`, `поиск`, `вид`. Все заданные фильтры действуют одновременно. Мир/раса — точное совпадение без учёта регистра; специализация и поиск — часть текста. Поиск смотрит ник, мир и описание. Неуказанные/неразбираемые старые уровни не проходят фильтр по уровню; значения не угадываются.

Четыре меню: игровая роль, класс, броня и вид списка. Виды: персонажи, люди, по классам, игровым ролям, броне, мирам, расам. Кнопки: назад, далее, сбросить все фильтры, весь отфильтрованный список TXT. На странице до восьми записей/групп; TXT содержит полные записи независимо от страницы. Данные перечитываются при действиях, меню работает 15 минут и после перезапуска открывается заново.

`/сводка-карточек по:классы` сразу открывает сгруппированную сводку с теми же меню. Уникальные люди считаются по Discord ID, альты — отдельные персонажи. В разрезе ролей один персонаж с несколькими ролями учитывается в каждой; суммы групп могут пересекаться. Реестровая карточка не подтверждает, что человек онлайн, свободен или сейчас состоит на сервере; нативный опрос ролей Discord сам по себе карточку в реестре бота не создаёт.

Примеры:
- `/карточки роль:хил класс:Шаман броня:кольчуга от:60`
- `/карточки раса:Орк вид:люди`
- `/карточки участник:@Игрок`
- `/сводка-карточек по:роли`

Проверка: всего 36 локальных тестов, включая сочетание фильтров, подсчёт людей и альтов, экспорт, повторную проверку прав, обновление данных, пагинацию и лимиты Discord.

Живая приёмка списков: `/карточки` выдал личное меню; фильтр хилов показал 0, сброс вернул тестовую карточку; группировка по классам показала одного Мага и одного человека; кнопка TXT выдала личный `карточки-команды.txt`. `/сводка-карточек` также вызвана через интерфейс Discord и выдала меню. Пагинация больших списков проверена локально, на живом сервере пока одна тестовая карточка. Исправлено обновление личных сообщений через webhook взаимодействия; после исправления меню проверено повторно.

## Панель и ручные заказы — 24.10.2026

Панель опубликована в #сбор-группы: `https://discord.com/channels/1563213738797047979/1563288428794224680/1563513813368569917`. Основные постоянные кнопки: создать сбор, найти игроков, мои записи, новый заказ, реестр заказов. `/панель-команды` обновляет существующую панель; её обработчики восстанавливаются при запуске.

`/заказ` открывает форму: название услуги, источник (вручную/FunPay/G2G), внешний номер, срок со смещением часового пояса, описание задачи. Это ручной ввод, интеграции с площадками отсутствуют. Для FunPay/G2G внешний номер обязателен; повтор источника и номера отклоняется. Ответственный — оператор-создатель.

Карточки публикуются в новом закрытом #реестр-заказов (`1563513809266544800`): доступ операторским ролям, боту и администраторам сервера. В карточках/описаниях нельзя указывать логины, пароли и персональные данные покупателей. Реестр и отчёты не удаляются вместе с временной комнатой состава.

Цикл: новый → набор → выполнение → ожидает отчёта → закрыт. Сбор создаётся кнопкой карточки заказа или связывается по номеру существующего сбора. Через `/сбор` оператор может указать `заказ:номер` и пользоваться всеми фильтрами состава. Один заказ связан с одним сбором, один сбор — с одним заказом; создание сбора и связь сохраняются одной транзакцией. Изменения статуса сбора обновляют внутренний статус заказа. Для закрытия нужны завершённый сбор и отчёт. Отмена активного заказа требует сначала завершить/отменить сбор; причина обязательна. Отмена сбора переводит заказ в «приостановлен»; повторный набор для такого заказа пока не реализован, оператор может завершить отмену заказа.

В карточке: создать сбор, привязать сбор, отчёт, закрыть заказ, отменить, полный TXT. Действия проверяют права оператора на каждом вызове. `/заказы` выдаёт реестр личным TXT и количество открытых заказов; `/заказы номер:1` — личная карточка. `/мои-записи` или кнопка панели выдают до 100 последних собственных записей. `/обновить-заказ` восстанавливает опубликованную карточку из базы; `/привязать-заказ` восстанавливает связь с уже существующим сообщением бота после неоднозначного сетевого сбоя. Новую карточку вслепую не пересылать.

История действий хранится в SQLite `order_audit`: номер заказа, исполнитель действия (для автоматической смены по сбору — системная запись), действие и время. Токен бота не входит в базу; секреты в задачу/отчёт не вводить. Текст отчёта хранится в `orders`; отдельный пользовательский экран истории и версии исправлений отчёта пока не реализованы.

44 локальных теста: атомарность связи, уникальность номера при конкуренции, запрет закрытия без отчёта, безопасная отмена, постоянные кнопки и повторная проверка прав формы. Сквозной тест официальным Bot API: технический заказ №1 → сбор №4 → готовность → выполнение → завершение → отчёт → внутреннее закрытие, статус в сообщении проверен. Это не реальная услуга и не платёж. Полный остаток работ — `outputs/FOREVER-ROADMAP.md`.

## Требования к отдельным местам — 24.10.2026

Расширенные замены и явка сняты с плана владельцем. Работающий резерв открытого набора учитывает требования мест.

Рекомендуемый порядок:

1. `/сбор название:Группа начало:2026-11-01T20:00+03:00 минут:60 танков:1 хилов:1 дд:3 настройка:True`. Запись закрыта, пока лидер настраивает места. Без параметра `настройка` обычный сбор сразу открывает набор, как раньше.
2. В следующих командах заменить `N` номером созданного сбора.
3. `/требование-сбора номер:N роль:хил мест:1 классы:Шаман` — одно место хила только для шамана.
4. `/требование-сбора номер:N роль:дд мест:2 броня:кольчуга` — два отдельных места дд в кольчуге. Третий дд и танк остаются по общим фильтрам.
5. При необходимости `/повторы-класса номер:N максимум:2`. Лимит действует для каждого класса во всей основе, включая разные игровые роли. `0` отключает ограничение.
6. `/состояние номер:N статус:набор` открывает запись.

Можно задать несколько групп мест одной роли. Классы перечисляются через запятую и означают варианты для этих мест; класс и броня в одном требовании действуют одновременно. Выделенные места не увеличивают общий размер. Сумма требований каждой роли не может превышать количество мест роли. Не распределённые по требованиям места остаются обычными.

Общие фильтры и требования отдельных мест применяются одновременно. Противоречия общим классам/броне и формально невыполнимые лимиты классов отклоняются. Тип брони берётся из карточки участника, из класса он не угадывается; фактическую экипировку бот не читает.

Если персонаж подходит хотя бы одному месту своей роли, но все подходящие места заняты либо мешает лимит повторов/пересечение времени, он идёт в резерв. Если ни одного подходящего места нет, запись отклоняется, включая резерв. Роль с нулём мест запись не принимает. При освобождении места выбирается первый резервист, которого можно разместить без нарушения требований. Уже существующие резервные записи после изменения правил сохраняются; неподходящие персонажи не повышаются. Участники могут перераспределяться между подходящими им логическими местами; персонаж, роль, основа/резерв и готовность от такого перераспределения сами по себе не меняются.

`/убрать-требование номер:N правило:R` возвращает места правила R к общим ограничениям. Номера правил видны на карточке и в TXT. Правила меняются только в статусах «настройка» и «набор». Если действующая основа перестанет соответствовать новым правилам, изменение отклоняется целиком; участников автоматически не исключают. При принятом изменении правил готовность сбрасывается и резерв пересчитывается. В зафиксированной и идущей группе правила не редактируются.

Карточка показывает заполнение групп мест и лимит повторов. Постоянная кнопка «Требования» выдаёт личный полный TXT до 40 мест; «Состав» включает требования и текущие записи. Класс и броня записанного персонажа сохраняются снимком, поэтому последующее изменение профиля не переписывает завершённый состав. Правила и их изменения сохраняются в базе; обработчики кнопок восстанавливаются после запуска.
